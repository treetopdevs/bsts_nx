## Findings considered and rejected (do not re-audit)

### From the 2026-06-20 pass

- **Gamma-sampler NaN "corruption"** (`distributions.ex` ~287-295): by-design fail-loud
  sentinel for Marsaglia-Tsang rejection-exhaustion; the proposed "floor to 1e-300"
  would reintroduce a silent point-mass the author deliberately rejected.
- **Smoother "eager-vs-defn covariance clamp mismatch"** (`smoother.ex` ~759 vs ~772):
  misread — both clamp *different* quantities in the same eager path.
- **R sidecar command injection** (`r_sidecar.ex`): well-defended (list-arg `Port.open`,
  isolated env, `:exclusive` 0600/0700 temp files, prefix-validated cleanup).
- **Nx 0.12 dependency lag**: current and version-aligned; no action. (Re-confirmed
  2026-07-08: 0.12 is the current line; only the 0.12.0→0.12.1 patch drift remains,
  recorded above as DEP-02.)
- **Relative-effect divide-by-zero**: already guarded (`validation.ex`, `@relative_effect_epsilon`).
- **No Dialyzer/Credo**: real DX gap but MED-effort with Nx false-positive noise; low
  leverage for a library this size.
- **Performance micro-items** (`rolling_baseline.ex:345`, `forward.ex:413`,
  `causal_impact.ex:331`): off the hot path, ~ms-scale; not worth the refactor risk.

### From the 2026-06-30 deep pass

- **Core numerical correctness & security**: thorough passes found **no new bugs**.
  The engine is well-defended (guarded `sqrt`/division, consistent NaN missing-data
  handling across eager/defn, verified backward-smoother indexing + lag-1 cross-cov,
  Cholesky jitter/eigenvalue fallbacks). The R-sidecar re-review confirmed the prior
  "well-defended" verdict (static R template, values via env vars — no R-code injection).
- **PERF (residuals host roundtrip)** (`gibbs_sampler/residuals.ex:19,31`): the
  `Nx.to_number` extracts a scalar that the host-side inverse-gamma variance sampler
  genuinely needs; near-free under the default BinaryBackend; on the explicitly-slow
  eager-MCMC path. Not a win.
- **PERF (spike_slab cluster)** (`gibbs_sampler/spike_slab.ex` — `List.replace_at` O(p²)
  gamma loop, nested-`Enum` covariance build, eager rank-1 updates, tuple-matrix XtX):
  real patterns, but dominated by the per-column g-prior matrix algebra in the same
  loop, in a module **deliberately optimized in `da81702`** ("pre-computed XtX/Xty"),
  and the rank-1 rewrite is HIGH-risk. Needs benchmarking to justify; not worth the
  risk now.
- **DEBT (two percentile methods)** (`causal_impact.ex:1065 linear_percentile` vs
  `utils.ex:387 percentile_interval`): **intentional** — linear interpolation for MCMC
  posteriors vs nearest-rank elsewhere. Consolidating changes statistical output; not a
  mechanical dedup.
- **DEBT (split the `CausalImpact` god module, 1102 lines)**: high effort, MED risk,
  debatable leverage for a library this size, and risky for a handoff executor.
- **DEBT (period-validator unification)** — `operational.ex:511`, `model_builder.ex:497`,
  `r_sidecar.ex:445`: **deferred, not rejected.** They return different shapes and
  `operational`'s omits the obs-length bound that `Validation.validate_study_periods!`
  enforces, so merging risks behavior change in the numerical index path. Plan 009
  explicitly scopes this out; it warrants its own plan with parity tests if pursued.
- **DEBT (non-empty validation dedup)** — deferred within plan 009: the messages differ
  across sites, so it needs message standardization + test updates; pull into its own
  follow-up.
- **DEBT (layering / spec-building scatter / Validation dead-code trace / Applications
  option-parsing)**: fuzzy/architectural, need judgment a handoff executor can't supply
  well; revisit only if they become pain points.
- **TEST (defn-vs-eager agreement for inv-gamma sampling)**: low added value — both the
  defn and eager inv-gamma samplers are already validated against the *analytical*
  inverse-gamma distribution independently (`distributions_defn_gamma_test.exs`,
  `distributions_inv_gamma_test.exs`), which is stronger than comparing them to each
  other.

### From the 2026-07-08 deep pass

- **"6 of 8 LiveViews render stale async results"** (part of DEBT-01): refuted on
  close read — `CounterfactualLive`/`MarketingLive`/`PolicyLive` compare completed
  results against current params; the rest have fixed scenarios where staleness
  cannot arise. The *dedup* (and crash-vs-busy split) remains a valid unplanned
  finding above.
- **heroicons GitHub-tag dependency** (`site/mix.exs`): stock Phoenix 1.8 generator
  pattern; `site/mix.lock` pins the immutable commit SHA, `app: false`/
  `compile: false`, sparse checkout. Reproducible and code-free; a hex wrapper
  would be a lateral move. No action.
- **`site/erl_crash.dump`**: untracked, gitignored, and outside the Docker COPY
  list — developer-machine housekeeping only.
- **Limiter as a bottleneck**: refuted — it's a counting semaphore; work runs in the
  caller's task, only fast acquire/release calls serialize. Monitor-based reclaim
  and double-release protection verified correct (and well-tested).
- **PERF-04 (SVG payload downsampling)**: **rejected 2026-07-08 (batch 4)**
  after a closer read of `charts.ex`: series are 144–156 points against a
  plot region far wider than that (well under 1 point/px, so downsampling
  would remove nothing), and `sx/sy` already round coordinates to 2 decimals
  (`charts.ex:646-647`). With plan 019's debounce killing the event
  frequency, no meaningful payload lever remains; any residual win would risk
  visual fidelity (e.g. anomaly spikes) for single-digit KB. Revisit only if
  a future demo plots >1k-point series.
- **BUG-05 (`DemandForecaster.aggregate` divide-by-zero in its `n == 0` branch)**:
  latent-only — unreachable through the public API today (`num_samples >= 1`);
  align with `Forecaster.aggregate_trajectories`'s zero-fill guard whenever that
  file is next touched. Not worth a standalone plan.
- **`Story.exec_badge` / site component-level duplication**: refuted — LiveViews
  consistently use the shared `story.ex`/`charts.ex` components; the real
  duplication is in LiveView Elixir scaffolding (recorded above).
- **Site parameter clamping / atom exhaustion / XSS / LiveDashboard exposure /
  secrets**: audited clean — server-side clamps everywhere, no `String.to_atom` on
  params, the one `raw/1` renders static Makeup output, dashboard is dev-gated,
  secrets env-sourced, container runs as `nobody`.
